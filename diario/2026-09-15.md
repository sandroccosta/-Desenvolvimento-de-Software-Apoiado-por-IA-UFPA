# Exercício: engenharia de contexto e decomposição de tarefas

- **Dupla:** Alexsandro Costa e Jhonathan Fagundes
- **Aula:** 15/09/2026
- **Modelo:** `llama3.2` rodando localmente no Ollama, com `temperature: 0`
- **Código:** [`aula3-engenharia-contexto/`](../aula3-engenharia-contexto/)
- **Tema:** consulta de filmes e séries com dados reais da OMDb
- **Pergunta:** "Quantas temporadas tem a série Dark e qual é sua avaliação no IMDb?"
- **Limite:** `MAX_PASSOS = 6`

O objetivo foi evoluir o laço agêntico da Aula 2 para consultar informações reais. O modelo escolhe uma tool, nosso código executa a consulta na OMDb, devolve o resultado ao modelo e repete o laço até receber a resposta final.

Neste diário, um passo é uma chamada ao modelo. Se o modelo pede uma tool no passo 1 e responde no passo 2, o laço levou 2 passos.

## Contexto e decomposição

Fornecemos ao agente o código da Aula 2, as regras específicas em `aula3-engenharia-contexto/AGENTS.md` e as decisões acumuladas em `aula3-engenharia-contexto/NOTES.md`. A implementação foi dividida em cinco etapas pequenas:

| Etapa | Entrega |
| ---: | --- |
| 1 | Contexto do projeto e configuração segura da chave |
| 2 | Cliente HTTP para consultar a OMDb |
| 3 | Tools e contratos de function calling |
| 4 | Laço agêntico com entrada pelo terminal |
| 5 | Testes, execução real e documentação |

Cada etapa foi validada antes da seguinte. A chave da OMDb ficou somente no arquivo local `.env`, ignorado pelo Git.

## As tools

| Tool | Parâmetro | Função |
| --- | --- | --- |
| `buscar_titulo(titulo, ano)` | título e ano opcional | Busca os detalhes de um título específico, incluindo avaliação, temporadas, gênero e diretor. |
| `pesquisar_titulos(termo)` | termo de pesquisa | Procura até cinco títulos semelhantes quando o nome está incompleto ou a pergunta é ampla. Não retorna avaliação ou temporadas. |

As descrições foram escritas para deixar clara a diferença entre pesquisar opções e obter os detalhes de uma obra. O terminal também registra cada tool acionada com a mensagem `Ferramenta usada: nome_da_tool`.

## Resultados

Na execução final, usamos o comando:

```powershell
python aula3-engenharia-contexto/agente.py
```

O resultado real foi:

```text
Digite sua pergunta sobre um filme ou série: Quantas temporadas tem a série Dark e qual é sua avaliação no IMDb?
Ferramenta usada: buscar_titulo

Resposta: A série "Dark" tem 3 temporadas e sua avaliação no IMDb é de 8,7.
Passos: 2
```

| Verificação | Resultado |
| --- | --- |
| Tool escolhida | `buscar_titulo` |
| Temporadas retornadas pela OMDb | 3 |
| Avaliação retornada pela OMDb | 8,7 |
| Passos do laço | 2 |
| Testes automatizados da Aula 3 | 21 aprovados |
| Teste de regressão da Aula 2 | 1 aprovado |

## Problemas encontrados e correções

| Tentativa | Comportamento observado | Correção aplicada |
| ---: | --- | --- |
| 1 | O modelo usou somente `pesquisar_titulos` e inventou 4 temporadas e nota 8,1. | Especificamos que essa tool não retorna detalhes. |
| 2 | O modelo pesquisou e depois consultou o mesmo título mais de uma vez. | Reforçamos no prompt que um título claro deve usar `buscar_titulo` uma única vez. |
| 3 | O modelo enviou um argumento extra para `buscar_titulo`, a chamada falhou e a resposta apresentou nota 8,1. | O despachante passou a aceitar somente os parâmetros declarados pela função. |
| Final | O modelo chamou `buscar_titulo`, recebeu os dados corretos e respondeu em 2 passos. | Comportamento aprovado. |

O primeiro plano também não destacava casos separados para chave inválida e limite diário da OMDb. Esses cenários foram incluídos nos testes antes da validação final.

## Análise

A primeira execução mostrou que uma integração funcionando não garante uma resposta correta. A OMDb estava acessível, mas a descrição vaga permitiu que o modelo escolhesse uma tool que devolvia apenas uma lista de títulos. Sem os detalhes necessários, ele completou a resposta com valores inventados.

As descrições das tools e o prompt de sistema mudaram a decisão do modelo. A filtragem de argumentos tornou a execução mais resistente quando o modelo gerou campos que não pertenciam à função. Com essas três correções, a pergunta direta sobre `Dark` exigiu apenas uma consulta à OMDb e uma chamada final ao modelo.

O limite de seis passos continua sendo a trava contra chamadas repetidas. Nos testes, uma resposta sem tool terminou em 1 passo, uma tool seguida da resposta terminou em 2, duas tools terminaram em 3 e chamadas contínuas foram interrompidas no passo 6.

## O que aprendemos

- Contexto bem escrito influencia diretamente qual tool o modelo escolhe.
- Tools diferentes precisam ter nomes, parâmetros e descrições que deixem seus limites claros.
- O modelo pode inventar informações quando recebe um resultado insuficiente; por isso, os dados devem vir da fonte externa antes da resposta final.
- O código que executa as tools deve validar os argumentos gerados pelo modelo.
- Testes automatizados verificam o laço e os erros sem consumir a API real, mas uma execução completa ainda é necessária para validar a integração.
- Registrar a tool usada e o número de passos facilita analisar o comportamento do agente.
